# Architecture guidelines — Back end

Every new implementation must follow the patterns already present in the code.

## General principles

- Follow the existing structure, names, and conventions; adapt to them instead of creating new ones.
- Prefer minimal and objective solutions; avoid unnecessary abstractions and complexity.
- **Reuse before creating:** check whether an equivalent DTO, service method, or exception
  already exists.
- Prefer a localized change to rewriting whole blocks.
- Deliver only what is used: no dead code, unused parameters, or imports.

## Formatting

- 4-space indentation and a 120-column limit.
- Parameters and arguments stay on the same line while they fit in 120 columns.

## Naming

| Artifact | Convention | Example |
| --- | --- | --- |
| Controller | `XxxController` | `VesselController` |
| Service | `XxxService` | `VesselService` |
| Repository | `XxxRepository` | `VesselRepository` |
| Entity | Singular English noun | `Vessel`, `Supplier` |
| DTO | `XxxDTO` (Java record) | `VesselDTO` |
| Exception | `XxxException` | `NotFoundException` |
| Fields and methods | `camelCase` | `registrationNumber`, `findById` |
| Endpoint path | Plural, kebab-case | `/class-entities` |
| Table and column | `snake_case` | `class_entity`, `tax_id` |
| Test method | `should_<behavior>_when_<condition>` | `should_throw_not_found_when_vessel_does_not_exist` |

## Database

- The schema changes only through a **new** Flyway script in `src/main/resources/db/migration/`,
  named `V<next number>__<description>.sql`.
- Primary key: `id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY`.
- Foreign key: `<table>_id BIGINT REFERENCES <table>(id)`, declared inline.
- One space between the column name and its type; no vertical alignment.

## Controllers

- `@RestController` and `@RequestMapping("/<plural-path>")` on the class.
- Constructor injection with `private final` fields.
- Return DTOs; `@ResponseStatus(HttpStatus.CREATED)` on create and `NO_CONTENT` on delete.
- No business logic and no `try/catch`: exceptions propagate.

## Services

- `@Service`, constructor injection, and Spring `@Transactional` on write methods.
- Look-ups by id use `findById(...).orElseThrow(() -> new NotFoundException("<Resource> not found"))`.
- To use another resource, call its service (example: `ClassEntityService.getClassEntity`
  used by `VesselService`).

## Repositories

- Interfaces extending `JpaRepository<Entity, Long>`, annotated with `@Repository`.
- Prefer derived queries (`findByName`); native SQL only when a derived query is not enough.

## Entities

- Lombok `@Getter`, `@Setter`, and `@NoArgsConstructor`.
- `Long` ids with `GenerationType.IDENTITY`.
- `@ManyToOne(fetch = FetchType.LAZY)` with an explicit `@JoinColumn`.

## DTOs

- Java records with a static `from(entity)` method.
- A relationship is represented by the id of the related resource (example: `classEntityId`).

## Errors

- `NotFoundException` (HTTP 404) already exists and must be reused.

## Tests

- JUnit 5 and Mockito for services (`@ExtendWith(MockitoExtension.class)`, mocked repositories).
- `ApiApplicationTests` loads the application and applies all migrations.
- Each test of a new feature references the business rule or acceptance criterion it checks
  (`BR-XX` / `AC-XX`) in its name or in a comment.

## Existing components to reuse

| Component | Use |
| --- | --- |
| `NotFoundException` | Unknown id (HTTP 404) |
| `ClassEntityService.getClassEntity(id)` | Load a class entity from another service |
| `state` column (two-letter UF code) | Pattern for data per Brazilian state, as in `vessel` and `supplier` |
